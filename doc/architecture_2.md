我们现在将系统重新划分为**标准的现代前后端分离架构（四层架构）**。

这个新架构的核心思想是：**“让 UI 变笨，让后端变强，让算力解绑。”**

以下是为 Oasis-AI 重新梳理的总体架构设计：

---

### 架构全景图：Oasis-AI 四层架构 (v2.0)

#### 第一层：展示与交互层 (Interface Layer) - **[同伴主导]**

* **物理载体：** 浏览器中的单文件或静态页面（`index.html`）。
* **核心职责：** 纯粹的视图层。负责展示聊天界面、呈现“链条执行面板”、管理用户的系统配置输入。
* **架构改造要求：** * **砍掉直连：** 绝对禁止直接向 `localhost:11434` (Ollama) 发请求。
* **砍掉存储：** 删除 JS 里手写的 TF-IDF 算法和基于 `localStorage` 的保存逻辑。
* **职责转移：** 所有的用户输入、点击“执行链条”操作，全部通过标准 HTTP 请求（如 `POST /api/chat`）或 WebSocket 发送给 Go 后端。



#### 第二层：核心调度层 (Orchestrator Layer) - **[你主导，Go 语言核心]**

* **物理载体：** 用 Go 语言编写的二进制程序（开发时跑在 Docker 里或原生运行）。
* **核心职责：** Oasis-AI 的“真正大脑”。
* **子模块设计：**
1. **API 网关 (API Server)：** 接收前端发来的请求，解决跨域问题，保护内部端口。
2. **流水线引擎 (Pipeline Engine)：** 解析前端发来的“链条配置”，用 Goroutine 优雅地控制模型 A（预处理）、模型 B（生成）、模型 A（后处理）的先后执行和并行等待。
3. **上下文管理器 (Context Manager)：** 在请求大模型之前，先拿着用户的话去“记忆层”检索相似记录，把结果无缝拼接到 Prompt 里。
4. **环境适配器 (Env Config)：** 根据配置文件动态决定 Ollama 的调用地址（识别是 Mac 的宿主机还是 Kali 的本地服务）。



#### 第三层：记忆与持久化层 (Storage Layer) - **[混合部署]**

* **物理载体：** SQLite 文件 + 轻量级向量数据库容器。
* **核心职责：** 数据的安全、离线持久化存储。
* **双库策略：**
1. **结构化数据 (SQLite)：** 存储所有的“模型配置”、“提示词列表”、“链条路径规则”。因为它是单文件数据库，极其适合离线打包，Go 原生支持良好。
2. **语义记忆数据 (Qdrant 或 ChromaDB)：** 真正的向量数据库，跑在 Docker 里。取代前端那个玩具级的 TF-IDF，实现精准的语义 Embeddings 检索，彻底解决“串记”问题。



#### 第四层：算力推理层 (Inference Layer) - **[环境解耦]**

* **物理载体：** Ollama 进程。
* **核心职责：** 纯粹的“无情打字机”，只负责接收带好上下文的 Prompt，吐出结果。
* **模型池设计：**
* **模型 A (Router/Formatter)：** 常驻内存的极小模型（如 Qwen2.5-1.5B），处理逻辑飞快。
* **模型 B (Roleplay/Generator)：** 玩家自己挂载的大参数模型。

### 核心数据流：当玩家发送一条消息时，发生了什么？

现在的标准数据流如下：

1. **[前端]** 玩家在 UI 点击发送：“你还记得我们在落日森林遇到的剑客吗？”前端将消息 JSON 发给 Go 后端。
2. **[Go 后端 - Context Manager]** 收到消息。先调用大模型生成这句话的 Embedding 向量，然后去 **Qdrant 向量数据库** 中检索“落日森林”和“剑客”相关的历史记忆。
3. **[Go 后端 - Pipeline Engine]** 组装出完美的 Prompt（包含历史记忆 + 玩家当前输入），发起 HTTP 调用，请求宿主机的 **Ollama (模型 A)** 提取核心意图。
4. **[Ollama - 模型 A]** 返回摘要意图。
5. **[Go 后端 - Pipeline Engine]** 再次发起调用，将意图发给宿主机的 **Ollama (模型 B)** 进行角色扮演回复。
6. **[Ollama - 模型 B]** 流式 (Streaming) 吐出回复。
7. **[Go 后端]** 将回复同步落盘到 SQLite，并将内容向量化存入 Qdrant，同时通过 SSE (Server-Sent Events) 或 WebSocket 把文本推回给 **[前端]** 展示。

### 跨平台开发与部署策略 (DevOps)

针对你的 Mac 和朋友的 Kali，目前的最佳实践环境划分：

| 组件 | Sisyphe的开发环境 (Mac) | Alix的开发环境 (Kali Linux) | 最终产品形态 (AppImage / 离线包) |
| --- | --- | --- | --- |
| **前端 HTML** | 挂载在 Go 的静态目录下 | 挂载在 Go 的静态目录下 | 打包在二进制/AppImage中 |
| **Go 后端** | 跑在 **Docker** 容器里 | 原生跑或跑在 Docker 里 | 编译好的原生二进制可执行文件 |
| **向量数据库** | 跑在 **Docker** 容器里 (Qdrant) | 跑在 Docker 容器里 | 随包附带的单文件轻量级版本库 |
| **Ollama算力** | **原生系统运行** (为调用 Apple GPU) | 原生系统运行 (调用 NVIDIA GPU) | 用户本机运行 |
